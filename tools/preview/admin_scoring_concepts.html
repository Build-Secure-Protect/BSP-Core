BSP Admin And Scoring Concepts

Four new features, three options for each. The 3D blocks turn when dragged, and the screens are working mock-ups with made-up players. Nothing here is in the mod yet.

1. Admin block and Admin UI

An operator-only block that opens the admin panel: every player's totems and levels, their Coin Vault balance, where their totems stand, and season controls.

The admin block

The admin panel

A. Roster Table

One sortable table with a row per player and action buttons on the row. Season controls sit in a bar on top. Densest view; best when you manage many players.

B. Player Cards

A card per player with their totems as tier pips and the coin breakdown. Easier to scan than a table, but shows fewer players at once.

C. List And Detail

Players on the left, everything about the selected player on the right, including each totem's server and coordinates. Season tools are a second tab. Most room for future features.

2. Coin Vault

A safe for Shatter Coins. Coins stored in it earn interest, the owner chooses who may open it, and anyone else has to lockpick it, much like stealing a totem.

The vault block

The vault screen

A. Safe Inventory

A normal storage grid that only takes Shatter Coins, with interest, access and security in a side panel. The most familiar to players.

B. Coin Ledger

No slots: one column per coin with deposit and withdraw buttons and a running total. Holds any amount, and reads like a bank balance, which suits the banking system you plan.

C. Tabbed Vault

Storage, Access and Security on separate tabs, with room for more later. Press "View as intruder" to see the lockpick screen a non-owner gets.

3. Score Screen

Screen blocks that join into one display, up to 8 wide and 6 high, showing the live leaderboard. An admin sets the layout, font, size and scroll speed. Use the controls to try the three layouts at any size.

These controls are the admin's settings (sneak + right-click the screen). A is a ranked list that scrolls when there are more players than rows. B shows the top three on a podium with everyone else on a ticker. C spotlights one player at a time in large type, best for tall or small screens.

4. Scoring system

The back end behind all three. Scores come from this server's own records on a single server, and from the shared MySQL database on a network. Three ways to turn totems into a score, shown on the same made-up players:

A. Totem Count

  1. Score = totems owned.
  2. Ties broken by the highest totem tier.
  3. Simplest to understand. Upgrading only matters in a tie.

B. Weighted Points

  1. Each totem scores by its tier: I = 1, II = 2, III = 4, IV = 7, V = 10.
  2. Rewards upgrading as well as stealing.
  3. A stolen high-tier totem is a big swing.

C. Season Points

  1. Points build up over the season: each totem earns its tier in points per day held, plus a bonus for every successful steal.
  2. Rewards holding totems, not just having them on the last day.
  3. Needs a history table; the season reset clears it.

Single server

  1. Totems, tiers and vault balances are read from the world's own records.
  2. Scores are recalculated when a totem changes hands, tier or owner, and cached.
  3. Screens and the admin panel read the cache.

Network with MySQL

  1. Each server writes its totems (with tier) and vault balances to the shared database.
  2. Each server reads the combined leaderboard on a timer, for example every 30 seconds.
  3. Screens and the admin panel show all servers; the panel names the server each totem is on.

Seasons and rewards

  1. "End season" stores the final standings, pays rewards, and resets totem upgrades.
  2. "Reward holders" pays everyone who holds a totem now.
  3. On a network one server runs it and the others pick it up from the database.
